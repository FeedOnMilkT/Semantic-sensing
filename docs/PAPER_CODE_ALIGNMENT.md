## ADE20K labels and teacher head

§5.1, lines 532–545 gives the foreground names in order: **bed, cabinet, table, car, sofa, armchair, bathtub, door, desk, mirror**; it says every other ADE20K label is background. This implies ten foreground classes plus background, so the final teacher has 11 logits in `configs/ade20k_rtformer_ten_object.yaml`. The paper does not explicitly state the output-head dimension: **11-way is an implementation inference**, not a verbatim paper requirement. The earlier 150-class teacher remains in `configs/ade20k_rtformer_paperhead.yaml` for the paper's prior/baseline setup; §5.4 does not say the final teacher is trained as a 150-class model.

`src/datasets/ade20k.py::remap_ade20k_labels` maps the official ADE20K source IDs (table convention: one-based 1–150) to train labels 1–10 in the paper's name order. Source 0 and all other categories map to background 0; ignore/padded pixels remain controlled by `ignore_index`. The mapping was checked against the dataset authors' [`objectInfo150.txt`](https://github.com/CSAILVision/sceneparsing/blob/master/objectInfo150.txt): bed 8, cabinet 11, table 16, car 21, sofa 24, armchair 31, bathtub 38, door 15, desk 34, mirror 28. The 150-class mode keeps its former source-0-to-ignore behavior. `SegMeter(exclude_classes=[0])` excludes background from the headline macro mIoU while retaining its false positives in each foreground class's union.

The final Hailo-oriented codec configuration uses Conv-BN-ReLU (`configs/phase2_mid_stage1_convbn.yaml`). GDN codec experiments use CompressAI's original GDN/IGDN by default. The previous clipped IGDN is available only as the explicit `bounded_igdn: true` numerical-stability ablation; it is not specified by `main.tex` and is not the deployed Conv-BN path.

## Precision and optional ImageNet initialization

§5.3, lines 497–499 specifies FP32 for the paper experiments. `configs/ade20k_rtformer_ten_object.yaml` keeps teacher training in FP32. The requested server ImageNet run uses BF16 autocast as a separate engineering setting; it does not change storage of downloaded images or annotation labels. The ImageNet loader decodes RGB bytes, transforms input tensors to normalized FP32, and keeps class labels as integer indices; BF16 applies to supported CUDA model operations during training.

`tools/pretrain_imagenet.py --config configs/imagenet_rtformer_original.yaml` trains the complete stage-1–5 trunk, with a temporary 1000-way classifier over pooled high and low stage-5 streams. Pooling/concatenation is an engineering choice because the paper does not specify the ImageNet classification head. The exporter drops that temporary head and DAPPM (which classification does not train); `RTFormer.load_pretrained()` requires every other trunk key and shape to match.

The ImageNet hyperparameters follow RTFormer supplement **Table 6**: 300 epochs, AdamW `5e-4`, WD `.04`, betas `.9/.999`, cosine minimum LR `5e-6`, five warmup epochs from `5e-7`, RandAug `(9,.5)`, color jitter `.4`, Mixup `.2`, CutMix `1.0`, random erasing `.25`, and drop path 0. Table 6 does not specify classifier head, crop/interpolation, label smoothing, or Mixup/CutMix switch probability. The implementation uses timm's `rand-m9-mstd0.5` interpretation (two RandAug ops), bicubic ImageNet crop, zero label smoothing, 0.5 mix/cut switch, and GAP-concatenation head; these are implementation choices, not exact reproduction claims. Physical batch 128 × 8 accumulation is the user's single-GPU adaptation to effective batch 1024. BF16 is also a user-requested engineering override; downloaded samples remain image bytes/RGB and transformed FP32 tensors. The paper's ADE teacher training remains FP32.
